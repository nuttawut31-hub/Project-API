หากมี 5 นาที ใช้ห้าช่วงแรกก่อน แล้วตอบคำถามจากเอกสาร

## โค้ดที่ควรเปิดเมื่อถูกถาม

- `backend/src/auth.js`: bcrypt เปรียบเทียบ hash, JWT อายุ 2 ชั่วโมง, ตรวจบัญชีซ้ำ, admin เท่านั้นที่ลบ
- `backend/src/index.js`: route และ SQL แบบใช้ `?`, ตรวจข้อมูลก่อนบันทึก
- `backend/migrate.js` กับ `migrations/002_auth.sql`: เพิ่มตารางบัญชีโดยรักษาตารางเดิม
- `frontend/app.js`: `api()` แนบ token, `load()` ดึง 3 รายการ, ช่องค้นหากรองข้อมูลที่โหลดแล้ว, ฟอร์มส่ง POST, ตัวเลือกสถานะต้องกด “บันทึก” จึงส่ง PUT และ “คืนค่าเดิม” ส่ง PUT กลับสถานะก่อนหน้า
- `backend/tests/api.test.js`: Supertest ทดสอบ 200/201/400/401/403/500; `tests/frontend.test.js` ตรวจ loading/success/error; `scripts/integration-check.js` ตรวจ MySQL จริง

## คำตอบสั้นสำหรับคำถามที่พบบ่อย

**ทำไมมี memberships?** สมาชิกสมัครได้หลายสาขาหรือหลายครั้ง ตารางนี้เก็บความสัมพันธ์ วันที่ และสถานะ

**ระบบปลอดภัยอย่างไร?** รหัสผ่านเก็บเป็น bcrypt hash, การเขียนต้องมี Bearer JWT และตรวจ role ใน API; การลบเป็น admin เท่านั้น

**ถ้า Open-Meteo ล้มเหลว?** weather service retry พร้อม timeout แล้วคืน fallback; ไม่ขัด flow หลัก

**เป็น microservices หรือยัง?** ยังเป็น Express แอปเดียว เอกสารสัปดาห์ที่ 13 เป็นแบบออกแบบหากจะขยาย

**coverage เท่าไร?** 20 tests ผ่าน, line coverage 74.13%; ต่ำสุดสามไฟล์อยู่ใน `coverage-report.md`

## หาก Demo สะดุด

- 401: ตรวจว่า login แล้วหรือ token อายุไม่เกิน 2 ชั่วโมง กด logout/login ใหม่
- 403: กำลังใช้ staff ลบข้อมูล ให้ใช้ admin เฉพาะตอนสาธิตสิทธิ์
- 409: ใช้อีเมลสมาชิกใหม่ที่ยังไม่เคยบันทึก
- 500/เชื่อมต่อไม่ได้: ตรวจ MySQL, `.env` และ `npm start`; ไม่แสดงรหัสผ่านบนจอ
